# Companion Dogs: performance contributions

Independent changes, written against Companion Dogs 0.7.4 (42.18+).

## Merged event handlers (U1): withdrawn

An earlier patch put every `CD.evAdd` handler on `OnTick` / `OnPlayerUpdate` behind one engine
listener. Measured offline against the game's Kahlua (`../tools/bench/BenchMerge.java`, 27 trivial
handlers, 42.21): one engine call per handler costs about 5.5 us per tick, the merged listener with
a `pcall` per handler about 12 us, and even without `pcall` about 8 us. The interpreter's Lua-to-Lua
call is dearer than the engine's Java-to-Lua call, so merging is a loss and was removed.

## tools/strip_perf.py  (V2)

Release-build step that removes `CD.pz` / `CD.pzd` wrappers from call sites (62 of them) in a copy
of the lua tree: `CD.pz("srv.x", CD.tickX)` becomes `CD.tickX()`. The instrumented source stays as
is for development. `strip_perf.py --selftest` runs its tests; every one of the 113 lua files still
parses afterwards.

`pz` returns at most two values and a direct call returns all of them; no call site uses a third.

## perf-*.patch  (scan changes, generated by ../tools/build_cd.py)

Apply from the mod's `42/media/lua` folder: `patch -p1 < perf-<file>.patch`. They depend on
`shared/CD_PerfNear.lua` (from CD_Perf) being added to the mod as well.

- `Threat.lua`: `CD.zsnap`'s square loop asks `CD.PerfNear.zombies` instead.
- `Hunting.lua`: `scanWildAnimals` loops over `CD.PerfNear.animals` instead of every square in
  a 33x33 to 49x49 box; same prey filter and tie rule.
- `Feed.lua`: `findTroughNear` uses `CD.PerfNear.feed`; dogs in a ranch zone first check the
  engine's own trough list (`getBehavior():getRandomTroughList()`), with a full search every 3rd
  call so a closer dish is still found.
- `Companion.lua`: idle gate. With no dog loaded, the 14 per-tick systems that only walk their own
  per-dog tables are skipped; the comment above `companionTick` lists them and why the rest stay.

`CD.PerfNear` serves each query from, best first: the zombies the engine reported to the dog in its
last `updateLOS` (CDPerf.jar, with a real scan at least every 2 s), one native box query
(CDPerf.jar), or a Lua snapshot per dog that collects every category asked for in the last 3 s in
one walk and refreshes it 400 squares per tick.

Not done: no in-game frame-time measurement. The gain is fewer Java -> Lua crossings and calls per
tick; measure it with your own profiler (`CD.perfCsvArm`) before claiming a number.
